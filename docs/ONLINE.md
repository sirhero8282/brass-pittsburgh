# 온라인 대국 · 실시간과 턴제

`dist/online.html`은 사람 네 명의 초대방이다. 기존 2인/4인 오토마 화면과 저장 키를 유지하며 별도 온라인 진입 링크만 추가한다. 현재 온라인은 정확히 4인이다. 계정, 공개 매칭, 랭킹, 채팅, 모드 전환, AI 대체는 제공하지 않는다.

## 플레이

1. 온라인 대국에서 실시간/턴제와 속도를 고르고 방을 만든다.
2. **초대 링크**를 친구들에게 전달한다. 입장자는 이름을 입력해 자기 자리를 받는다.
3. 네 명 모두 준비하면 방장이 시작한다.
4. 각자 자기 손패로 카드 → 행동 → 세부 선택 → 행동 확정을 진행한다. 확정된 행동은 되돌리지 않는다.
5. 브라우저를 닫아도 게임은 서버에 저장된다. 같은 기기의 내 대국 목록이나 **개인 재접속 링크**로 돌아올 수 있다. 개인 링크는 자리의 접근 권한이므로 다른 사람에게 공유하지 않는다. 회원 계정이 없어 개인 링크와 기기 저장을 모두 잃으면 자동 복구할 수 없다.

## 시간 정책

| 모드 | 빠름 | 보통 | 느림 | 무제한 |
| --- | --- | --- | --- | --- |
| 실시간 | 초기/상한 3분, 턴 시작마다 +1분 | 초기/상한 5분, +2분 | 초기/상한 10분, +3분 | 시계 없음 |
| 턴제 | 자기 턴 12시간 | 자기 턴 24시간 | 자기 턴 48시간 | 마감 없음 |

실시간은 현재 플레이어의 시계만 흐른다. 첫 턴에는 초기 시간으로 시작하고 이후 자기 턴이 시작할 때 보충한다. 두 행동 사이에는 보충하지 않는다. 턴제도 첫 행동 후 마감을 갱신하지 않으며 다음 플레이어로 차례가 넘어갈 때 새 마감을 정한다. 연결 끊김/새로고침으로 시계가 멈추거나 초기화되지 않는다. 서버 시각이 기준이다.

시간 초과는 자동 패스/패배/오토마 대체를 발생시키지 않는다. 현재 참가자 이외의 사람이 시간을 연장할 수 있다. 대국 중단은 네 명의 동의가 있어야 한다. 친구 초대방용 정책이며 경쟁전의 제재/이탈 처리와 구분한다. 활동 시간대와 야간 정지는 아직 없다.

## 서버와 비공개 정보

- `multiplayer/worker.mjs`: Cloudflare Worker + 방마다 SQLite Durable Object. HTTP 명령, WebSocket, 하이버네이션, 영구 저장, 차례/마감 알림.
- `multiplayer/room.mjs`: 준비, 시작, 개인 시계, 턴 마감, 인증된 자리, 버전 검사, 중복 명령 영구 기록, 전원 중단 동의.
- `multiplayer/engine.mjs`: 기존 FourHuman/FourPlayer 규칙을 재사용한다. 행동하는 자리를 임시 0번으로 교환하고 모든 소유권/순서/보상/정산을 원래 자리로 돌린다. Automa 후보 가지치기로 사람의 선택지를 제한하지 않는다.
- 클라이언트는 합법 선택지의 번호만 전송한다. 서버가 현재 상태로 선택을 재실행해 금액/카드/자원/소유권/순서를 확정한다. 요청으로 보낸 상태/결과/플레이어 ID는 채택하지 않는다.
- 시작과 2시대 카드 분배는 암호학적 셔플을 사용한다. 첫 턴 순서와 미공개 유전 보상 위치도 별도로 셔플한다. 공개 배치로 카드/유전 순서를 역산할 수 없도록 기존 32비트 시드 셔플과 분리한다.
- 플레이어 투영은 허용한 필드만 전송한다. 다른 사람의 패, 모든 덱의 순서, seed, AI 메모리, 미공개 유전 값, 자리 인증 키는 제외한다. 원본 상태 전체를 publicState로 전송하지 않는다.
- 취소 가능한 미리보기에는 보충/2시대 새 손패와 새로 공개되는 유전의 보상·효과·로그를 보내지 않는다. 유전을 연 뒤 추가 선택이 필요하면, 먼저 명시적으로 행동을 고정한 뒤 보상을 공개한다. 고정한 카드/첫 건설은 바꿀 수 없고, 고정 정보는 서버에 저장해 재접속 후 이어간다.
- HTTP/WebSocket 핸들러와 알림용 alarm은 방 안에서 직렬 처리한다. 상태와 명령 처리 기록은 한 저장 문서로 함께 기록한 다음 각자의 view를 전달한다. 시계 갱신은 초마다 쓰지 않고 기준 시각과 잔여 시간으로 계산한다.

## 알림

‘차례 알림 켜기’를 누른 사람이 브라우저에서 허용한 경우에만 Web Push를 등록한다. 새 차례와 턴제 마감 1시간 전/시간 초과에 알린다. Service Worker는 알림만 담당하고 기존 게임의 요청을 가로채거나 캐시하지 않는다. 알림에 손패/자리 인증 키를 넣지 않는다. 실제 전달은 기기·브라우저의 알림 지원과 설정, 푸시 서비스에 의존한다. iOS 등에서는 홈 화면 설치가 필요할 수 있다.

서버는 VAPID_PRIVATE_KEY / VAPID_PUBLIC_KEY / VAPID_SUBJECT를 Cloudflare secret으로 받는다. 개인 키는 소스·배포 파일에 넣지 않는다. 푸시 구독 주소는 브라우저 제공 서비스 도메인만 허용하고 리다이렉트를 따르지 않는다. 기기 알림 허용이나 실제 사용자에게 전송하는 검증은 자동으로 수행하지 않는다.

## 개발과 배포

`multiplayer/`에서 lockfile에 맞춰 의존성을 설치하고 `wrangler dev --port 8792`로 서버를 실행한다. Pages 미리보기는 `node scripts/serve.cjs` (4194). 로컬 주소에서는 자동으로 로컬 서버를 사용한다. Worker 설정의 허용 출처와 `dist/online/config.js`의 공개 주소를 함께 관리한다. Worker를 별도 배포한 다음 기존 Sites/Pages의 정적 파일을 게시한다.

검증: `node --test tests/multiplayer.test.cjs`; 전체 검사는 `node --test tests/*.test.cjs`. 실행 중인 서버 검사는 `node multiplayer/smoke.mjs [endpoint]`. Smoke는 오직 새로 생성한 합성 검증방에서 네 HTTP/WS 접속, 각 모드 124행동, 재접속, 패 비공개, 중복 명령을 검증한다. 기존 사용자의 대국을 시험 데이터로 사용하지 않는다.

현재 범위: 친구 초대방 초기 버전. 공개 매칭용 생성 요청 제한, 계정 복구/다른 기기의 대국 목록 동기화, 서버 버전 간 규칙 고정/진행 중 방 마이그레이션, 운영 보관/정리 정책은 추가 설계가 필요하다. 알림 실패가 확정된 행동을 취소하지 않는다.
