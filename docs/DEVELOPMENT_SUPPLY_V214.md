# v214 development: independent source component per resource

The user authorized the corrected development rule after reproducing the failure: two paid developments may use one iron from an accessible Buffalo industry and one steel from the West market even when these are different components of the acting owner's network. Normal city-bound construction still requires its own connected component. Existing source priority, prices, ownership of rail bonuses and Vanderbilt opt-in for the player are unchanged.

Shared `developmentSupplyPlan` quotes resources in order with one source city per unit, reserving prior units before selecting later ones and restoring all stock afterward. `developmentResourcePlans` considers the acting owner's distinct existing components and deduplicates physically equivalent source combinations. A disconnected opponent-only component cannot be an origin; an opponent source reached by an owned component remains usable. Same-resource units, bonuses and fixed market stock cannot be counted twice.

The player retains the existing tile/resource selectors. The source-plan selector displays actual origins and the full cost rather than one misleading common origin. No inventory, money or tiles change before confirmation. Confirmation is followed by an exact source/connectivity/price/budget recheck, then consumption of those exact sources. Picker/confirmation cancellation is inert. There is no change to free-development handling.

Automa generation, legality validation, real execution and search use the same per-resource component plan. `sourceCity` remains the first origin for compatibility; new `sourceCities` records every unit. Legacy single-origin actions are re-quoted rather than blindly trusted. Changed/stale/forged prices or stock are rejected before payment. Supply optimization is cached only locally by tile count within one candidate-generation call; there is no persistent state or save migration. Strategy weights and the rejected locomotive experiment remain untouched.

Regression `tests/development-supply.test.cjs` covers app and Lab engine: both owners, Buffalo/West purity and $5 price, same-resource stock sharing, opponent access, train bonus ownership/exhaustion, actual candidate execution versus search, stale/forged/unaffordable sources, player action confirmation, both cancellation points and stale-after-confirmation. Existing build/resource/sale/reward tests remain active. Release verification and two-site publication results are recorded in CODEX_CONTEXT.md. No live saved game is edited or reset.
